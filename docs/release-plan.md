## 二、「能一起发版」的定义

不是功能全，而是这五条同时成立：

1. **可用**：四个入口在**生产域名 + HTTPS** 下无阻断性错误
2. **可控**：出问题能一键关掉工作台入口，不影响主站充值和登录
3. **可查**：任务失败、扣费异常能在日志/后台定位
4. **可算**：每个用户的消耗和产出对得上账
5. **可退**：回滚不需要改数据库

## 三、阻塞项（不做完不能发）

### P0 — 生产化（必须）

| # | 事项 | 说明 | 验收 |
| --- | --- | --- | --- |
| 1 | `FYT_TICKET_SECRET` | 现在是默认值，票据可伪造 | 生产用随机 32 字节，写进密钥管理 |
| 2 | 生产 nginx 子域 + 证书 | 预发是 HTTP，生产必须 HTTPS | `create.fytapi.com` 证书就绪，HSTS |
| 3 | 产物目录持久化 | 容器重建不能丢作品 | 挂卷或对象存储，重启后作品还在 |
| 4 | 生产环境变量清单 | `FYT_INTERNAL_API`、`ARTIFACT_DIR`、`NEXT_PUBLIC_STUDIO_BASE_PATH` | 一份 `.env.example` + 部署文档 |
| 5 | **不要**打开 `ARTIFACT_ALLOW_PRIVATE` | 只在预发用，生产会绕过 SSRF 防护 | 生产配置里没有这一项 |

### P1 — 稳定性（必须）

| # | 事项 | 为什么 |
| --- | --- | --- |
| 6 | 画布会话外部化 | 现在存进程内存 + 文件，**多副本会串号**；首发单副本可接受，但必须写进限制说明 |
| 7 | 上游失败的处理策略 | 视频提交后上游超时可能已扣费，要有明确规则（退 / 不退 / 补偿） |
| 8 | 限流与并发 | 单用户并发上限，避免打爆上游 |
| 9 | 监控告警 | 任务失败率、上游 5xx、扣费异常，至少要有日报 |

### P2 — 体验（强烈建议）

| # | 事项 | 说明 |
| --- | --- | --- |
| 10 | 模板系统 | 分镜 / 广告 / 口播，降低「不知道写什么」的门槛 |
| 11 | 错误文案 | 现在失败只有一句通用提示，要能告诉用户「是额度、渠道还是上游」 |
| 12 | 空态引导 | 首次进入给示例提示词 |
| 13 | 移动端可用性 | 画布在手机上基本不可用，至少保证图片/视频/作品可用 |

## 六、与 fyt 同期发版的做法

以下独立子域承载应用的旧方案已被主站 `/create` 同源方案替代；摘入口需同时维护 `/create` 和 creative-agent 专属 API 路由，详见新部署手册。

```
发版顺序：
1. 先发 fyt（网关/控制台）      ← 主站始终可用
2. 再发工作台（独立容器）        ← 失败只影响创作入口
3. nginx 打开 create 子域       ← 一键开关
4. 观察 30 分钟 → 上公告
```

回滚：

```
nginx 里把 create.fytapi.com 的 server 块注释掉并 reload
→ 工作台入口消失，主站和已生成的作品不受影响
```

**不要**把工作台和主站放进同一次容器发布，那样回滚会连带主站。

## 七、风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 上游（seedance / gpt-image）不稳定 | 用户点了没结果但扣费 | 失败自动退费 + 公告说明 |
| 单副本内存态 | 重启丢画布会话 | 首发接受，文档写明；第 2 阶段改 Redis |
| 成本失控 | 视频单价高，被刷 | 单用户日额度 + 并发限制 |
| 内容合规 | 生成内容风险 | 提示词过滤 + 举报入口（法务确认） |
| 画布手机端不可用 | 移动用户流失 | 移动端默认进图片页 |

## 八、发版之后（不在本次范围）

按优先级：

1. **状态外部化**（Redis）→ 多副本、任务队列
2. **成片能力**（拼接 / 字幕 / 配音）→ 真正的「漫剧」
3. **角色一致性**（角色库 + 参考图编辑）
4. **本地 Canvas Agent + MCP**（专业用户）
5. **自建算力**（ComfyUI 后端 + GPU 调度）
