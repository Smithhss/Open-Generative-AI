# fyt 创作工作台全功能接入计划

> 执行方式：按独立模块细化实施任务，使用 executing-plans 逐项执行；本文件为整体路线图，不授权提交、推送、数据库迁移或生产部署。

**Goal:** 保留开源原版布局，将可落地功能逐项接入 fyt 的身份、模型、钱包、任务和成本体系。

**Architecture:** Next 工作台继续运行在 `/create`，fyt Go 负责身份、模型分发和扣费。复用已有页面与控件；MuAPI 专属服务按功能替换，不将 JWT 传作原 apiKey，也不新建第二套钱包。智能体会话和工作流定义属于业务数据；不能把现有 Relay 或 Task 误当完整智能体/工作流引擎。

**Tech Stack:** 现有 Next/React、studio 及三个子模块、Go/Gin、既有 PostgreSQL/Redis；本计划不引入或升级依赖。

## 2. 所有模块的处理范围

| 模块 | 能做的交付 | 当前可推进 | 外部依赖/限制 |
|---|---|---|---|
| 账户与余额 | 已完成基础；补真实请求后的余额与费用展示 | 是 | 不另建用户和钱包 |
| 智能体 | 角色模板、系统提示词、多轮文本、流式回答、自定义角色 | 是 | 首版为文本助手；工具调用需渠道实际支持 |
| 提示词助手 | 优化图片提示词、视频分镜、营销文案、翻译 | 是 | 走现有文本模型，真实请求会消耗额度 |
| 工作流编辑 | 节点画布、输入/输出/文本节点、图校验、保存 | 是 | 编辑器不等于执行器，移除原 MuAPI 执行入口 |
| 工作流执行 | 文本串联首版，之后图片/视频节点 | 文本部分可做 | 服务端执行、归属、次数/费用限制需实现 |
| 图片 | 单张文生图→图生图→多图 | 代码可先做 | 渠道、采购价、真实收费验证后开放 |
| 图层与图片编辑 | 本地导入、图层调整和导出；AI 分层/抠图另接 | 先验证本地子集 | AI 分层、扩图、超分各需对应模型，不由普通生图自动获得 |
| 视频 | 文生视频、图生视频、任务进度与恢复 | 代码可先做 | 插件/渠道、时长与尺寸计费、异步任务 |
| 音频 | TTS、转写；音乐和音效另列 | 代码可先做 | `/v1/audio/*` 不等于音乐生成渠道已就绪 |
| 唇形同步 | 视频/人像与音频组合生成 | 后接 | 专属供应商端点、上传与任务体系 |
| 动作控制 | 参考动作视频驱动角色 | 后接 | 专属模型能力，不能当普通图生视频 |
| 换体/角色替换 | 输入视频及参考角色生成 | 后接 | 专属模型、参考素材、异步结算 |
| AI 剪辑 | 上传视频、片段预览；自动高光/字幕/导出分开实现 | 先分析处理链 | 原 runClipping 是服务调用，自动剪辑需要转写/渲染 |
| Vibe 动效 | 动效描述与编辑，之后预览/渲染 | 文本草案可做 | 原 runMotionGraphics 为服务调用；代码预览必须隔离执行 |
| 电影工作室 | 剧本/分镜文本→逐镜图像→视频 | 文本阶段可做 | 多阶段任务、角色一致性不是现成保证 |
| 营销工作室 | 文案和广告脚本→商品图/广告视频 | 文本阶段可做 | 图像和视频渠道及各阶段费用 |
| AI 网红 | 人设/内容规划→参考素材→图视频 | 文本阶段可做 | 固定角色一致性与素材管理 |
| 设计智能体 | 先画布/项目编辑，再文本驱动画布，再多模态 | 先适配本地子集 | 原会话/技能/工具运行时需替换；高复杂度 |
| 探索应用 | 只展示 fyt 已验收模板和可运行入口 | 是 | 外部模板清楚标外链，不承诺全部内置 |
| MCP/CLI | 文档与现有 fyt API 使用说明先行 | 是 | 新 MCP 服务是单独后端项目；禁止向用户浏览器暴露平台 Key |
| 作品/历史 | 本地草稿→服务端私有记录与素材→跨设备恢复 | 可设计/开发 | 数据库迁移与存储方案需确认；代理下载不等于持久保存 |

## 3. 分阶段交付

### 阶段 A：立即可推进的文本能力与入口状态

**目标：** 不等媒体渠道，先让智能体入口真正可用。

**涉及文件：** `components/StandaloneShell.js`、`components/fyt/FytShell.jsx`、`lib/fyt/session.mjs`（沿用 getAccessToken）、新增 `lib/fyt/chat.mjs`、`components/fyt/FytAgentStudio.jsx`；模板先使用工作台本地静态数据。

- [ ] A1：统一模块状态，区分可用、界面预览、待渠道和未接入；避免所有入口都显示同一句占位。
- [ ] A2：保留原智能体卡片/聊天视觉，提供通用助手、提示词优化、分镜脚本、营销文案模板；模板不冒充具有工具的自治智能体。
- [ ] A3：模型只取用户实际可用且支持聊天的集合，不能将界面模型别名当成不同真实能力。
- [ ] A4：使用内存会话向同源 `/pg/chat/completions` 发送对话，解析流式内容；支持停止和重新发起，不自动重试收费 POST。
- [ ] A5：首版自定义角色与对话按 user.id 存本地；注明“本机保存”，不承诺跨设备。对话只保留完整轮次，发送前限制上下文长度。
- [ ] A6：流结束/失败后刷新余额，实扣来自服务端日志；用户点击停止不承诺一定退款。

**验收：** 两账号历史隔离；角色提示生效；一轮请求正常显示流式回答；401 回登录；断流不自动重发；刷新恢复本机历史；浏览器网络只请求同源。付费验证在预算/渠道授权范围内进行，未授权时以 mock 验证并标记真实调用未验收。

**不含：** 联网搜索、文件检索、工具调用、自动执行、多代理、共享发布。

### 阶段 B：本地编辑能力、模板与服务端业务数据

**目标：** 让无渠道的编辑功能可使用，并单独完成跨设备保存基础。

**涉及文件：** `packages/studio/src/components/LayersStudio.jsx`、`DesignAgentStudio.jsx`、`AppsStudio.jsx`，及实际调用到的画布持久化/网络模块；服务端新增 studio 业务 controller/model/router，具体名称在独立实施计划确定。

- [ ] B1：先断开网络检查图层/画布的本地导入、移动、缩放、文本和导出路径；仅开放确实可本地执行的子集，AI 按钮继续关闭。
- [ ] B2：所有新增编辑器按 user.id 隔离；匿名内容不迁入已登录账号，不复用旧 apiKey 短哈希历史。
- [ ] B3：探索应用改为已接入模板目录；移除 fyt 模式兴趣登记的远端调用，外链明确标识。
- [ ] B4：将角色、会话、画布、工作流定义的服务端保存拆为单独数据变更，列出表、索引、用户归属、大小限制、迁移及回退，确认后再执行迁移。
- [ ] B5：服务端从认证上下文获取 user.id，每次读写校验归属；数据库不保存 JWT/供应商 Key。首版不建设公共市场。

**验收：** 本地子集无需任何模型请求；跨设备功能另验收两账号越权请求、刷新恢复、并发编辑冲突提示。没有存储迁移时不得宣称云端保存完成。

### 阶段 C：工作流编辑与最小文本执行

**目标：** 开放真实可保存、可运行的文本工作流，不先建设通用自动化平台。

**涉及文件：** `WorkflowStudio.jsx`、`WorkflowUI.jsx`、`packages/Vibe-Workflow/packages/workflow-builder/src/` 实际 API 客户端；fyt 新增执行 controller/service/model（先做独立详细设计）。

- [ ] C1：复用画布，首版节点仅输入、提示词模板、文本模型、输出；未支持节点不可添加。
- [ ] C2：定义图 JSON 版本，保存前检查未知节点、缺失参数、环和断开的输入；首版只接受有向无环图。
- [ ] C3：Go 服务端按图拓扑逐节点执行；输入只能引用前置节点输出，限制图规模、节点调用次数和输出长度。
- [ ] C4：每个模型节点复用原分发/扣费服务；内部调用不拿浏览器 JWT 调自身 HTTP，不使用平台万能 Key，也不为工作流外层重复计费。
- [ ] C5：记录运行/节点状态与实际请求关联；失败时保留已经完成且收费的结果。中止只停止未开始节点，不承诺退还已发生费用。
- [ ] C6：媒体节点等其单独验证通过后再加入，不提前显示为可执行。

**验收：** “输入→文案→改写→输出”可运行；跨用户不可读图或运行；环被拒；失败不重扣；并发运行互不污染；节点费用可追溯。禁止任意 HTTP、代码执行、外部回调与定时触发进入首版。

### 阶段 D：图片与共用素材/作品基础

**目标：** 首个真实媒体闭环。可提前写代码，渠道就绪后才放开生成。

**涉及文件：** `ImageStudio.jsx`、新增 fyt 图片适配文件、fyt `controller/playground.go`/`router/relay-router.go`/限流相关文件、现有 Task/产物/成本模块。

- [ ] D1：沿用已制定集成计划，为会话增加图片入口；验证 relay mode、用户组、额度和 token_id=0 限流边界。
- [ ] D2：仅一张文生图，归一 OpenAI data[] 的 URL/base64；请求号记录为 `X-Oneapi-Request-Id`，不作为幂等键。
- [ ] D3：模型列表由用户可用能力和已验证参数交集决定；外部别名与上游模型映射可追溯。
- [ ] D4：上传素材检查大小、类型和归属；作品元数据与文件保存分别设计。远端下载仅允许验证过的上游/产物来源，防止任意 URL 抓取。
- [ ] D5：明确按张/分辨率采购成本，和 fyt 成本维护者对齐；未知成本显示待核算，不以占位 1 Token 或零成本计算利润。
- [ ] D6：供应商及预算确认后真实验证一张；成功、供应商失败、余额不足各自核对扣费与退款。之后再加图生图、批量、抠图/超分/扩图。

**验收：** 图片有效、用户实扣正确、失败净扣正确、供应商账单与成本有证据关联、历史归属正确、无自动收费重试。Mock 只能证明协议及本地结算逻辑。

### 阶段 E：视频、音频及专用媒体工具

**目标：** 复用 fyt Task 和插件逐项接入，避免每个页面建立一套轮询。

**涉及文件：** `VideoStudio.jsx`、`AudioStudio.jsx`、`MotionControlStudio.jsx`、`LipSyncStudio.jsx`、`RecastStudio.jsx`、现有 fyt task router/controller/plugin。

- [ ] E1：先一个文生视频模型，再图生视频；任务提交后刷新仍能恢复，终态停止轮询。
- [ ] E2：归一 NOT_START/SUBMITTED/QUEUED/IN_PROGRESS/SUCCESS/FAILURE/UNKNOWN；UNKNOWN/超时作为待核对，不自动当失败退款。
- [ ] E3：音频依次做 TTS、转写，再按真实渠道决定音乐/音效；分别验证文本/音频长度及单位价格。
- [ ] E4：唇形、动作控制、换体每个都独立确认端点、输入素材、产物及价格，逐项开放。
- [ ] E5：按秒、时长、尺寸、音轨等实际采购单位对账；同一个任务重复回调/查询不能重复结算。

**验收：** 任务归属、刷新恢复、失败结算、产物访问和供应商账单关联通过；不以“存在插件”替代实测。

### 阶段 F：组合创作与高级智能体

**目标：** 在已验证单项能力之上开放组合产品。

**涉及文件：** `CinemaStudio.jsx`、`MarketingStudio.jsx`、`AiInfluencerStudio.jsx`、`ClippingStudio.jsx`、`VibeMotionStudio.jsx`、`DesignAgentStudio.jsx` 及三个子模块实际消费的 API。

- [ ] F1：电影/营销/网红先开放已完成的文本规划；图/视频按阶段独立确认、展示费用和结果。
- [ ] F2：复用工作流运行记录，处理中断时保留前序产物，重跑明确范围；不一键重跑全部收费步骤。
- [ ] F3：剪辑先明确素材处理/转写/渲染执行位置，再开放自动高光、字幕与导出；不将原远端 runClipping 当成浏览器剪辑器。
- [ ] F4：设计智能体先替换 token 存储和会话 API，再接受限工具集；读取素材/写画布/生成媒体各有输入校验及归属检查。
- [ ] F5：动效生成如涉及代码预览，先完成隔离渲染方案；生成代码不得直接运行在携带 fyt 会话的页面上下文。
- [ ] F6：MCP/CLI 先提供准确的现有 API 文档；若要新建 MCP Server，另立项目范围和密钥权限方案。

**验收：** 每个步骤可单独观察、失败可定位、费用不重复；角色/镜头一致性按样本验收，不承诺模型天然保证。各组合产品独立交付，不以“高级模块全做完”为一个验收点。

## 4. 推进顺序与每轮规则

1. **立即：阶段 A 文本助手**，再做 B 的本地编辑和模板；这是当前最有实际价值且不等媒体的路径。
2. **随后：B 的服务端保存与 C 文本工作流**。数据库方案明确后才安排迁移；纯编辑预览可以先交付。
3. **渠道到位：D 图片→E 视频/TTS/转写→专用媒体工具**。这条线不必等待 C 完成。
4. **能力稳定：F 各组合创作与设计智能体**，按单模块拆开，不承诺一轮全部迁移。

每项：读代码及预发实际配置→列最小改动→本地验证→按授权更新本机预发供用户体验→用户确认后完成该项必要测试和审查。提交/推送/生产部署必须另有明确授权。

不提供总工期承诺：文本首版、持久化、工作流执行、媒体适配属于不同规模项目；先交付 A，再根据实际改动量估算后续。不将全部菜单同时解锁视为完成。
